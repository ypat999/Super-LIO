5b.【2026-10-22 最新结论，详见五-D】
   - 楼梯道是螺旋：每层净转 269°，所以任何 ∝ 转角的误差都会长成“逐层同向同角度”。
   - 已逐项否决：观测层注入（Σobs 仅占预测 −2.0%，符号 51/49）、陀螺零偏（真实温漂被
     ESKF 跟住，残差 <1e-2 deg/s）、陀螺 scale（1.002 时全程 yaw 差 <0.2°，而理论应差 7.9°）
     ⇒ **yaw 由 scan-to-map 配准钉住，不是陀螺积分出来的**。
   - 去畸变用原始陀螺（未扣 bg）是真 bug，已修；但实测不改变 deg/m，只影响帧内 roll 斜切。
   - 当前定位：偏置在**配准层**，量级 0.0886 deg/m ÷ 72.6 deg/m = 1.22e-3 × 转角
     （基线 1.98e-3，配准越强残留越小）；下一步见 D.7，另有跨框架对照见五-E。
   - imu_na/ng 的“未平方”是**方差口径**不是 bug 漏改，禁止直接补平方（见第四节 [配置语义]）。

5d.【2026-10-22 时序消融，详见五-F】"雷达时间基准滞后"假设被证伪，但换来一条硬约束
   - 新假设：若逐点时刻统一多算 Δ，去畸变会把整帧云刚体多转 ω·Δ，配准吸收后
     每帧位姿偏 −ω·Δ ⇒ 累计 yaw 偏置 = −Δ·累计转角（与"每层同向同角度、往返相消、
     只动 yaw、窗外好点不帮忙"四条现象全部吻合）。定量要求 Δ≈1.22 ms。
   - 实验（新增 lio.sensor.lidar_time_offset，5 组 430 s 同窗口）：
     Δ=−3/0/+3/+10 ms 的等效 Δ 只有 −0.19/0/+0.19/+0.31 ms（3%~6% 传递，R²≈0.02）；
     +50 ms 时 map 从 15 万点爆到 2240 万点、轨迹发散 ⇒ 旋钮有效，是假设本身不成立。
   - 由此得到硬约束：**整帧云刚体多转 0.29°，位姿 yaw 只让位 3% ⇒ yaw 是被地图钉住的，
     不是被点云拉过去的**。这同时解释了 D.5（陀螺 scale 0.2% 只让 yaw 动 <0.2°）。
   - 处置：时移/scale/去畸变零偏这一整类"点时刻→云形状"的机制全部出局；
     下一步只剩地图闭环（插入/关联规则、刚性 ΔT 修正），见五-F.5。

一、现象与判读（不变）
--------------------------------------------------------------------------------
1. 楼道/楼梯间等狭窄空间出现漂移，分两种：
   (a) 微量持续漂移，方向具有持续性；
   (b) 偶发跳变，不可预测。
2. 中大型空间可稳定匹配已有点云，问题不显著。
3. 12 层楼梯点云（按 y 坐标着色）呈现：
   - 本应笔直的井道壁变成平滑弧线（横向偏移随高度增长）；
   - 上下两组平台板之间存在绕竖轴的相对旋转（“扭曲”，非单纯倾斜）；
   - 误差随高度单调累积，无来回震荡。
   判读：属于 (a) 累积型漂移。若为 (b) 主导，应出现单层突然错位、墙面分叉/重影，
   而不是连续弧线。

二、代码事实校准（动手前必读；行号以 b528aec 为准）
--------------------------------------------------------------------------------
1) 实时管线顺序（src/lio/super_lio.cpp:378-415 stateProcess）
   Propagation_Undistort -> PublishBodyCloud -> DownSample -> Observe
   -> ApplyDeltaCorrection -> UpdateMap -> Output -> enqueueDense
   配准与建图都用“抽稀 + 去畸变 + 体素化”后的 ds_undistort_；发布不用体素化结果。

2) 输入过滤与抽稀（src/ros/ROSWrapper.cpp:768-813 livoxHandler；stdMsgHandler 同）
   - tag 过滤、range 过滤（blind/maxrange）、intensity 过滤（intensity_min）
   - filter_rate 隔点抽稀：lidar.pc = 抽稀点（供实时链路）
                         lidar.pc_full = 全量点（供 DenseThread / PCD）
   - filter_offset 每帧“对称振荡”，避免固定相位削同一批点；
     但本配置 enable_filter_offset=false，实际是固定步长抽稀（见三、[降级]）

3) 去畸变（super_lio.cpp:1013-1146）
   - 输入是 measures_.lidar.pc（已抽稀），输出 scan_undistort_full_。
     命名里的 "full" 指“未体素化”，不是全分辨率；真实全量在 pc_full。
   - query_time > back_time 的点直接 continue 丢弃（b528aec），不再原样透传。
     现在唯一缺的是丢弃计数（见 L4 埋点）。

4) 体素降采样（super_lio.cpp:1202-1205 + include/OctVoxMap/VoxelGridFilter.h:47-79）
   - 类型是 VoxelGridClosest<PointType>，不是 pcl::VoxelGrid。
   - leaf = lio.sensor.voxel_fliter_size（本配置 0.25 m）。
   - 每个体素保留“离体素中心最近的真实点”：参考点 = round(p/leaf)*leaf，
     单遍 argmin，整点拷贝（offset_time 保留），不做质心平均。
     与论文 III-A “center-based selection … better preserves original measurements
     than standard voxel filters”一致。
   - lio.sensor.enable_downsample 只在 DownSampleOnly() 生效；
     正常 LIO 模式下 DownSample() 无开关，体素恒开。
   - 运行时用 ros2 param set 改 voxel_fliter_size 不会生效（setLeafSize 仅在 init 调用）。
     所有体素相关实验必须重启节点。

5) 观测构建（super_lio.cpp:44-94, 1244-1377）
   - 5 近邻：KNNHeap<5, V3>（定长、无堆分配），HKNN 按子体素距离分组遍历、可提前终止。
   - 平面拟合：calc_plane_coeff，5 点 QR 解 ax+by+cz+1=0；
     逐点残差 > lio.observe.plane_fit_threshold（默认 0.15 m）→ 整点拒绝。
   - 残差门：compute_error 返回 length > 81*e^2（即 |e| < sqrt(range)/9）。
   - 权重：w = obs_weight（默认 1000），超 Huber 时 w *= delta/|e|；
     delta = huber_delta_base(0.05) + huber_delta_scale(0.003)*range。
     → 当前所有点除 Huber 外等权，完全没有“法向质量”概念。
   - 雅可比：J = [p×n ; n]，因此 HTVH.block<3,3>(3,3) ≈ Σ w·n·n^T，
     退化方向就是 n 分布张不满的方向。

6) 地图（include/OctVoxMap/OctVoxMap.hpp:101-115, 265-303）
   - 粗体素 = lio.hash_map.vox_resolution（0.25 m），再分 2×2×2 子体素（0.125 m）。
   - 每个子体素一个代表点 μ + 计数 n：
       空：μ=首点（真实点）；否则 n<20 且 |p-μ|≤0.1 m 时做增量均值，否则丢弃。
   - 注意：门限是相对 μ，不是相对子体素中心；但 μ 不会漂出子体素——同一子体素的
     点都在格子内，增量均值是凸组合，必然仍在格子内（第六轮已实测证伪，见五-B.3）。
   - 均值本身是论文明确的设计目标（incremental denoising，方差 ~1/n），不要当 bug 删。
     真正可调的是“均值 vs 真实代表点”（rep_mode）与合并门限 merge_dist。

7) 输出（super_lio.cpp:1415-1424 body，1451-1464 world）
   - cloud_body / cloud_world 都由 scan_undistort_full_（抽稀、去畸变、未体素化）生成。
   - DownSampleOnly 用的也是同一个 VoxelGridClosest（1234-1236），只是受 enable_downsample 开关。

8) 异步全量链路（super_lio.cpp:556-608）
   - DenseThread 消费 pc_full，复用同一 IMU 轨迹去畸变 + delta 修正；
     有界队列 >3 帧丢最旧；world 全量只用于 PCD 落盘。

9) 参数生效方式（src/ros/ROSWrapper.cpp:478-527）
   - on_set_parameters_callback 只改全局变量；filter_rate 等“每帧读取”的参数能即时生效，
     voxel_fliter_size 等“init 时装载”的参数不能。实验时一律重启节点。

[P0-2] 18x18 信息矩阵在 float 下求逆（未修）
  位置：src/lio/ESKF.cpp:264  M18 Y_pred = P_pred.inverse();
        src/lio/ESKF.cpp:310-313  Qk = Yk.inverse();
  依据：alias.h 里 scalar=float；ESKF.cpp:340 已有 0.5*(P+P^T) 对称化补丁；
        scalar=float 时退化方向条件数可达 1e7，Qk 基本没有有效位数。
  改法（每帧 2~4 次 18x18，成本可忽略）：
        M18 Y_pred = P_pred.cast<M18d>().inverse().cast<scalar>();
        M18d G_inv_d = G_inv.cast<M18d>();
        M18d Yk_d = G_inv_d.transpose() * Y_pred.cast<M18d>() * G_inv_d
                  + HTRH.cast<M18d>();
        Qk = Yk_d.inverse().cast<scalar>();
  可选（供 CSV）：
        Eigen::SelfAdjointEigenSolver<M18d> es(Yk_d);
        double ev_max = es.eigenvalues().maxCoeff();
        double ev_min = std::max(1e-12, es.eigenvalues().minCoeff());
        double cond_yk = ev_max / ev_min;
  验收：Qk 无非有限值；cond_yk 是否随飞行时间单调升到 1e5 以上；
        跳变帧是否伴随 cond 峰值。若无相关性，只是“去隐患”。

[P1] 法向质量没有进入权重（已实现，2026-10-21）
  现状：所有点等权（Huber 只管残差大小，不管平面本身可不可信）。
  实现：calc_plane_coeff 多输出 max|dist|（复用已有循环，零新增遍历）；
        Observe 两处权重乘 q=1/(1+(fit_res/σ)^2)，σ=lio.observe.normal_sigma。
        后续迭代复用首轮质量权重（need_converge 时不会重算平面）。
  实测：见五-B。RMS 0.102 m，迭代 3.54→3.25，cond(Yk) 5142→4062；
        但末段 z 从 0.01 翻到 0.34 m，本数据无法判定优劣。

[P2] OctVox 的 μ 未锚定子体素中心（已实现，实测恒等 → 剔除）
  原假设：merge 门限 |p-μ|≤0.1 m 相对 μ，μ 可被持续偏置的观测拉出子体素。
  实现：AddPoint 均值后按需夹回子体素包围盒（lio.hash_map.clamp_mu）。
  实测：expc4 与基线轨迹逐位相同（RMS 0.000 m）。原因是几何上的恒等：
        进入同一子体素的点都在该子体素内（按 floor 分配），增量均值是它们的凸组合，
        必然仍在子体素内，clamp 永远不触发。原假设不成立，方案剔除。

[设计边界，不是 bug] 退化方向无约束
  依据：J.tail<3>()=n，HTVH.trans ≈ Σ w·n·n^T；楼梯井轴向 n 覆盖不足。
  模型是纯 point-to-plane + 增量地图，无 scan-to-scan、无子图、无回环。
  结论：持续漂移的“发生条件”来自这里，“漂移方向”由 IMU 偏置/尺度/外参决定。
        埋点只能确认真相；根治需增加约束或后端（SC-PGO/回环/楼层先验）。

[配置语义] imu_na/ng 是方差口径，不是标准差（平方被注释掉）
  位置：ESKF.cpp:95-110，et2 = et; // * et;（ev2/eg2/ea2 同样），随后直接
        Q_.diagonal() << et2,et2,et2, ev2,ev2,ev2, eg2,eg2,eg2, ea2,ea2,ea2。
  ⇒ 配置值被**原样当作过程噪声协方差**用。lio.sensor.imu_na/ng=0.1 的实际 σ=0.316。
  影响面：决定先验与观测的信任比，也影响 bg/ba 的随机游走强度（eg2/ea2）。
  **不要直接把这些参数平方**（2026-10-22 补充）：
    - 本分支所有可用配置（livox_360*/hesai/r3live/NCLT/M2DGR...）的 imu_na/ng 都是
      0.1（NCLT 为 0.01）、imu_nba/nbg 都是 1e-4 这一套数值，是**按方差口径**长期调出来的；
    - 一次性平方等价于把过程噪声压小 10 倍（0.1→0.01），而五-A 已测过 na/ng→0.01 的
      效果（户外回环上更快、更贴基线），楼梯 bag 上还没有等效数据；
    - 真正受影响的只有"预测/观测相对权重 + 零偏随机游走"，与 D.6 认定的"配准层比例型
      偏置"不是同一机制，改了也不保证改善楼梯间，反而可能整体改变滤波器行为。
  若要动，按"等价降噪"而不是"补平方"来做：先固定 Q 的其它块，只把 ng/(na) 按 x0.1、
  x0.01 两档跑楼梯 bag，看 deg/m 是否单调收缩；不收缩就说明该旋钮与本问题无关，回退。

实验 1：法向质量加权（P1）【已实现并跑完一轮，结果见五-B】
  假设：楼梯间“有偏沿轴约束”主要来自勉强拟合出的倾斜法向；
        按拟合质量降权应减少慢漂，且不显著减少有效点。
  代码改动（4 处）：
    1. super_lio.cpp calc_plane_coeff（当前签名见 :47）增加输出参数：
         inline bool calc_plane_coeff(const int N, const std::array<V3,5>& points,
                                      std::array<double,4>& abcd,
                                      scalar* max_abs_dist = nullptr)
       在现有的逐点 |dist| 循环里累加最大值（不要新增一次遍历）：
         scalar m = 0;
         for (i...) { dist = ...; if (|dist| > g_plane_fit_threshold) return false;
                      m = std::max(m, std::abs(dist)); }
         if (max_abs_dist) *max_abs_dist = m;
    2. 新增成员 std::vector<scalar> fit_res_vec_;（与 abcd_vec_ 同尺寸、同 resize 位置）。

    4. 新参数（ROSWrapper.cpp:196-213 declare/get + 478-527 回调；params.cpp/h）：
         lio.observe.normal_weight_en   bool    默认 false

实验 3：filter_rate × voxel 尺寸（P3，参数实验，先不改代码）【户外回环已完成，见五-A】
  目的：确认“削点”到底来自时间抽稀还是体素。
  运行矩阵（每次只改一个）：
    (a) baseline:             filter_rate=6, voxel=0.25
    (b) rate:                 filter_rate=3, voxel=0.25
    (c) rate:                 filter_rate=1, voxel=0.25
    (d) voxel:                filter_rate=6, voxel=0.15
    (e) voxel:                filter_rate=6, voxel=0.20
  重要混淆项（必须在结论里写明）：
    - HKNN 候选表是“体素索引”的（HKNN_neighbor_voxel 最大偏移 ±2 体素），
      物理搜索半径 ≈ 2×vox_res。voxel 0.25→0.15 时，搜索半径 0.5→0.3 m，
      “邻居更少”会同时恶化法向，实验 (d)(e) 不是纯粹的“点密度”对照。
      若要把 voxel 尺寸作为干净变量，需要同时改 HKNN 列表（或按比例扩到 ±3 体素）。
    - orders_min_dis2 是硬编码的绝对 m² 阈值，不随 vox_resolution 缩放；
      换体素尺寸后提前终止对应的几何距离变了，只影响搜索深度/耗时，不影响正确性。
  采集：n_knn_fail / n_plane_fail / n_effect / ptsize、fit_res 分布、
        htvh_t_eig3/eig1、逐层 ΔT、耗时。
  判据：
    - 若 (b)(c) 明显优于 (a) 而 (d)(e) 改善有限 → 主因是时间抽稀，
      后续优化方向是“保留墙面点”的抽稀策略（例如按空间分布抽稀，而不是隔点抽）。
    - 若 (d)(e) 显著改善且 n_plane_fail 下降 → 体素尺寸确实在削法向，

A.3 为什么 imu_na/ng 变小反而更快（本次唯一“免费”的正向改动）
  改的是什么：实验 5/6 只改 lio.sensor.imu_na 与 lio.sensor.imu_ng
  （加速度计/陀螺的过程噪声），0.1 → 0.01 → 0.001；imu_nba/nbg 仍为 1e-4。
  ESKF.cpp:99-102 的平方被注释，所以填进去的数直接进 Q 对角（单位是方差）：
    0.1 → σ≈0.316；0.01 → σ=0.1；0.001 → σ≈0.0316。
  加速机理（推断，证据见下；确证需第六节 L2 的 iters 埋点）：
    1) Observe 计时包住的是整个 ESKF::UpdateObserve 迭代循环（最多 4 次，
       super_lio.cpp:401），不是单次观测构建；
    2) Q 变小 → Predict 里 P 增长更慢（ESKF.cpp:234），更新后 P_=Qk 也更小，
       下一帧 Y_pred=P^{-1} 更大 → 增益更小 → 每次迭代的 dx 更小；
    3) 收敛门是 dx_.lpNorm<Inf>() < kf_quit_eps(0.001) 且 iter>0（ESKF.cpp:325），
       dx 变小 → 更早触发 break → 少一轮“要重搜 KNN”的满代价迭代（iter>2 才置
       need_converge_，第 4 轮本来就便宜）。
    迭代次数之外没有别的成本来源：每帧参与配准的点数、体素数完全不变。
  证据：差异在每个 60 s 统计窗口都成立，不是一次性抖动——
    Observe 各窗口（baseline）：2.77 / 3.75 / 4.69 / 4.13 / 4.54 ms
    Observe 各窗口（imu0001）：  2.09 / 2.67 / 3.34 / 3.07 / 3.34 ms
    baseline/imu001 ≈ 1.14 倍，baseline/imu0001 ≈ 1.34 倍，逐窗口单调。
  代价与风险：修正更小 = 更依赖 IMU 递推。本段数据前 ~50 s 静止（|ω|≈0.015 rad/s）、
    IMU 质量好，所以轨迹反而更贴基线（RMS 0.031 m）；若零偏大/标定差，0.01 会把
    IMU 误差带进轨迹，那时它不会“免费”。0.001 更快但相对基线偏差翻倍（0.062 m），
    且无真值无法判断方向，故本轮推荐 0.01 而不是 0.001。

A.4 结论（仅限这段户外回环数据）
  1) 算力：唯一显著项是 Observe；fr1 最坏 42 ms、平均 16.25 ms（预算 16%），
     仍安全但收益无法证明 —— 轨迹与基线只差 0.27 m RMS，不建议作为默认。
  2) 体素：0.25→0.20/0.15 不提速、不多点（+3~5%）、末段 z 反而抬高 0.43~0.51 m；
     且 HKNN 搜索半径随 vox_res 缩小，属混杂变量。维持 0.25。
  3) IMU 噪声：0.1→0.01 同时更快（−0.55 ms/帧）且更贴基线（0.031 m），
     末段 z 0.02 vs 0.01；是唯一可“免费”采用的改动，建议在楼梯数据上复测后
     再决定是否写成默认值。
  4) 回环一致性：7 组经过起点附近时的水平距离 4.54~4.94 m，差异 <0.4 m；
     该指标对本次参数不敏感，不能作为区分依据。

A.5 局限（读结论前必看）
  - 数据是户外建筑回环，没有楼梯井那种单轴退化段，也没有 RTK/动捕真值；
    “漂移变小/变大”只能相对基线，不能当绝对精度。楼梯间结论必须用楼梯 bag 重跑。
  - 每组 300 s、1x 实时；WSL2 上 wall-clock 有跳变（play_wall 记录 ~278 s），
    所有指标按消息时间戳对齐并裁到共同窗。
  - 每组独立重启节点、独立建图；组间 CPU 状态（频率/负载）不能完全一致，
    但逐窗口排序稳定（见 A.3），故不改变方向性结论。

B.3 结果分析
  1) 埋点与开关默认值不改行为（已证）：
     expc1 与 exp0_baseline 轨迹 RMS 0.000 m、末位置 0.000 m；60 s 冒烟跑与
     300 s 基线在重叠段逐点吻合到 1e-3 m。可以放心把 debug CSV 当观测手段。
  2) Observe 的组间差是噪声，不是收益：
     在点数完全相同、逻辑几乎没变的组之间，Observe 在 3.07~4.45 ms 间跳，
     说明单次运行的地板噪声约 ±0.7 ms。HKNN 少搜 3 组没有提速（4.23 ms）：
     耗时主要在已经发生的体素查找/压实遍历，提前终止只省后半段。
     结论：用本指标比较 <1 ms 的改动需要多次重复，不能单跑定论。
  3) 法向质量加权（expc2）：机制确实生效——迭代 3.54→3.25、cond(Yk) 5142→4062，
     说明高残差平面被降权后，观测信息更“软”，dx 更小、收敛更早。
     代价是约束分布改变：RMS 0.102 m，末段 z 从 0.01 翻到 0.34 m。
     没有真值，无法判断这是“更准”还是“更松”；在退化段它可能帮倒忙
     （本就缺约束的方向被进一步降权），需楼梯数据判定。
  4) 地图代表点 rep_mode=1（expc3）：几乎无影响（RMS 0.013 m，末段 z 不变）。
     本数据以大面积平面为主，增量均值与“离子体素中心最近的真实点”之差远小于
     0.125 m 子体素尺度，不足以改变法向/残差。地图点数 +679 是轨迹微差带来的，
     不是 OctVox 直接产物（落盘 map.pcd 来自 dense point_map_，不是 OctVox）。
  5) μ clamp（expc4）是恒等操作：轨迹逐位相同。原因见第四节 [P2]——
     同一子体素的点全在格子内，凸组合的均值不会越界，clamp 永不触发。
     该方案从候选中剔除；真正会改变代表点的是 rep_mode 与 merge_dist。
  6) 收紧 merge 门限（expc5，0.1→0.05）：代表点更贴近首批观测、更新更少，
     RMS 0.109 m、末段 z 0.37 m，和法向加权同一量级、同一分支。
  7) HKNN 组数 6→3（expc6）：机制明确生效——有效点 97.2%→95.3%（−1.9 pp），
     KNN 邻域不足 2.3%→4.4%（翻倍），cond 略降。代价是邻域点变少，
     轨迹 RMS 0.107 m、末段 z 0.37 m；没有换来速度。不建议作为默认。
  8) 提前终止阈值 ×0.5（expc7）：影响最小（RMS 0.020 m，地图 −1.1 k 点）。
     说明在 0.25 m 体素 + 室外场景，5 邻域通常在 group0~2 就满足阈值，
     后续组的遍历本来就很少发生——这也解释了“减组不提速”。
  9) 末段 z 是双峰，不是连续误差：4 组末段 z≈0.01 m，3 组≈0.34~0.37 m，
     而路径长全部 227.6 m、回起点水平距离全部 4.93~4.94 m（revisit_z 同步翻转）。
     如此小的机制扰动就能把回环末段推到另一支，说明这段数据的 z 漂移对扰动
     高度敏感，单看末段 z 会把“分支翻转”误读成“机制变差”。
     后续评估应以整段轨迹 RMS + 多指标（z_min/z_max/revisit_z）联合判断，
     并优先在退化场景上验证。

B.4 结论
  1) 这段户外回环上，四类机制都没有产生可判定的改进（RMS ≤0.11 m），
     也没有带来速度收益（均在地板噪声内）。
  2) μ clamp 已被证伪（数学恒等），从 backlog 删除。
  3) rep_mode=1 与 order_scale 的影响最小，可作为保留开关；法向加权与
     merge 门限会显著改变约束分布，必须用楼梯/退化数据判定方向。
  4) 埋点回答了“漂移是不是匹配层坏了”：不是。KNN 失败率 2.3%、Qk 始终有限、
     cond(Yk) 稳定在 5e3 量级而未爆炸——与“退化方向无约束 + IMU 零偏积分”的
     既有判断一致，继续在观测权重上打转收益有限。
  5) 下一步优先级：楼梯 bag 上复测 expc1/expc2/expc6，重点看
     cond(Yk)、HTVH 条件数是否随高度上升，以及有效点占比是否随楼层下降。

B.5 局限
  - 仍是户外回环，无退化段、无真值；“机制无差异”不等于“在楼梯间无差异”。

D. yaw 系统性偏置溯源（2026-10-22，回答"逐层同向同角度偏转"）

D.1 几何前提：这是螺旋楼梯道，每层净转 ~269°
  用 odom 的 z 与解缠 yaw 拟合（只取 |vz|>0.15 的爬升段）：
    expy1_m2_dbg  上升 dθ/dz=+74.5 deg/m、下降 +70.1 deg/m，合并 +72.6 deg/m
    exp0_baseline 上升 +74.4、下降 +69.9，合并 +72.4 deg/m
  层高 3.7 m ⇒ 每层净转 269°，方向恒定；一次下楼 yaw 从 0 走到 −3928°（10.9 圈），
  回程又走回 0。这就是"每层同向同角度"的前提：任何与**转角**成比例的误差，
  在每层转同样角度的螺旋里都会沉淀成每层恒定的 yaw 偏转。

D.2 观测层注入：否决
  expy1_m2_dbg 12781 帧 / 1277 s，世界系 yaw 逐帧分解（exp/yaw_bias_split.py）：
    Σ 后验增量 −163.40°，Σ IMU 预测 −167.53°，Σ 观测净修正 +3.38°（占预测 −2.0%）
    Σ|预测| 22667°，Σ|观测修正| 783°；每帧 |修正| RMS 0.0927°（max 0.710°）
    修正符号 正/负 = 51.0%/49.0%；corr = +0.02459·pred + 0.00059（R²=0.537）
  ⇒ 没有可辨识的常值修正项，符号对称。单看这一层不能判定"观测是偏置源"。

D.3 陀螺零偏：否决
  灵敏度（1e-3 rad/s 常值零偏折算全程世界 yaw）：bg_x −1.95°、bg_y +2.07°、bg_z +26.73°。
  bag 直读 /livox/imu 安静窗（2 s 陀螺 std<0.05 rad/s，exp/imu_bias_drift.py）：
    t=0    +3.975 / −1.481 / +0.494 deg/s
    t≈1120 +3.390 / −1.410 / +0.350
    t≈1200 +3.180 / −1.430 / +0.240
  ESKF 自估 bg 首尾：+3.855/−1.462/+0.489 → +3.072/−1.419/+0.169 deg/s。
  两者趋势一致（bg_z 净降 0.32 deg/s 都被跟住）⇒ 零偏是传感器真实温漂、且被滤波器跟住，
  残差量级（<1e-2 deg/s）不足以解释 0.33°/层。

D.4 去畸变用原始陀螺：是真 bug，但不是答案
  原 Propagation_Undistort / enqueueDense 的 omega_body 直接用 imu.gyr（含零偏），
  与 ESKF 传播的 (gyr−bg) 不同源：bg_x≈3.9 deg/s、单帧 94 ms ⇒ 帧尾 ~0.36° 常值 roll 偏斜。
  已改为 imu.gyr − bg_（super_lio.cpp 约 1035/569 行）。
  对照 expy3_m2bg（同 m2 参数，只换二进制）：墙面斜率 −0.0887 deg/m，
  expy1_m2_dbg 为 −0.0886 ⇒ 完全不变。说明它只影响 roll 偏斜，不进入 yaw。

D.5 陀螺 scale：否决（关键实验）
  新增 lio.sensor.imu_gyr_scale（默认 1.0，作用在 imuHandler 取到原始角速度后，
  Predict 与去畸变同源），expy5_gsc2 = 1.002（+0.2%），其余同 m2：
    墙面斜率 −0.0863 deg/m（vs 1.0 时的 −0.0887），全程 yaw 轨迹与 expy3 逐点差 <0.2°
  若 yaw 由陀螺决定，0.2% 的 scale 在 3928° 转角上应造成 7.9° 差异；实测 <0.2°。
  ⇒ **yaw 不是陀螺积分决定的，是被 scan-to-map 配准钉住的。**

D.6 结论：偏置在配准层，量级 ~1.2e-3 × 转角
  同一 bag、同一陀螺输入，只改配准参数就改变了 yaw：
    exp0_baseline  vs expy1_m2_dbg（voxel 0.2 vs 0.15 + HKNN3）：1F 段 yaw 差 2.3°
    （末段又收敛到 0.09°，说明是"下楼途中长出来、回程又退回去"的可逆偏置）
    expc1_base（基线复跑）与 exp0_baseline 逐点差 <0.01° ⇒ 流程本身确定性良好
  与墙面斜率一致：
    基线 −0.1437 / −0.1438 deg/m（两次），m2 −0.0886 / −0.0887（含 bg 修正）、
    m4r3 −0.0899，gyr_scale1.002 −0.0863
  偏置/转角 = 0.0886 / 72.6 = 1.22e-3（基线 1.98e-3）。配准越强（voxel 0.15+HKNN3），
  残留越小 —— 这与"配准层是偏置源、观测权重决定残留"自洽。
  同时解释三个现象：①每层同向同角度（269°/层恒定）；②只有 yaw（偏置按转角记账，
  位置由 accel+配准决定，1e-3 量级在 xyz 上看不出）；③往返一趟后回到 ~0
  （final_yaw 0.72°，下楼 10.9 圈与上楼 10.9 圈相消）。

D.7 下一步（按性价比排序，均需单实例串行，约 22 min/次）
  1) kf_max_iterations 4→8：检验偏差是否来自迭代未收敛/线性化残差，判据看 deg/m 是否收缩。
  2) 观测权重（g_obs_weight 1000）上下各一档：若 deg/m 随权重单调变化，说明是"地图吸引扫描"
     的增益问题，而不是几何退化。
  3) 把 ApplyDeltaCorrection 的**刚性** ΔT 改成按点时刻分配的修正：
     当前每帧 yaw 修正是刚体施加到整帧的，帧内不同时刻的点仍带着 ΔR 的残差斜切，
     方向上与转动同号，是"比例型偏置"的天然候选；改动量最大，需先由 1)/2) 排除。

D.8 两条代码级疑点的处置状态（2026-10-22 收口）
  疑点 A：去畸变用了未扣零偏的陀螺（用户读码发现，优先级最高）
    代码事实：undistortCloud() 里 ic.omega_body = imu_gyr[j]（原始 gyr），而 ESKF::Predict()
      用 body_omega_ = 0.5*(imu.gyr + last_imu_.gyr) - bg_。两条路径角速度不同源，
      帧内每点会被多转 bg*tau（bg_x≈3.9 deg/s、帧长 94 ms ⇒ 帧尾 ~0.36° 常值 roll 偏斜）。
    处置：已修（super_lio.cpp Propagation_Undistort 与 enqueueDense 都改成 gyr - bg）。
    结果：expy3_m2bg 与 expy1_m2_dbg 的墙面斜率 −0.0887 vs −0.0886 deg/m，逐层 yaw 不变
      ⇒ 该 bug 真实存在，但只影响帧内 roll 斜切，不进入 yaw 账本（详见 D.4）。
    说明：这是"该修"，不是"能治扭曲"；保留修复，不再作为候选解释。

  疑点 B：BuildNoise() 没有平方，而配置注释口径可能是标准差
    代码事实：ESKF.cpp:95-110，et2 = et; // * et;，Q_ 直接吃配置值。
    结论：当前分支的数值是**按协方差口径**调出来的（几十份配置同一套数），
      语义上"imu_na/ng=0.1 ⇒ σ=0.316"；平方会等价于把过程噪声压小 10 倍。
    处置：**不改**。理由与判别方法见第四节 [配置语义] 条目。
    若将来要做，按"等价降噪"扫描（x0.1 / x0.01 两档）而不是补平方，且判据必须用
    楼梯 bag 的 deg/m 与 1F low_dyaw，不能只看户外回环 RMS。

  顺序建议（回答"比调抽稀参数更值得优先验证"）：
    A 已证伪为 yaw 主因（D.4）；B 属于滤波器权重旋钮，机制上与 D.6 的比例型偏置不同层。
    所以 D.7 的 1)/2) 仍排在最前，B 排在它们之后做"权重灵敏度"对照即可。

    FAST-LIO 在 IMU_Processing 里做 acc *= G_m_s2 / mean_acc.norm() 自动归一到 m/s²；
    Point-LIO 的 acc_norm=1.0 语义就是"输入按 g"，代码做 acc * G_m_s2 / acc_norm。
    两边都与本 bag 自洽，**不需要改**。
  - 话题：/livox/lidar 是 livox_ros_driver2/msg/CustomMsg，两框架 lidar_type=1 都按
    CustomMsg 订阅；QoS best_effort 订阅与 bag 的 reliable 发布兼容。
  - odom 话题：FAST-LIO → /Odometry（且是 lifecycle node，必须 configure+activate
    之后 publisher 才生效）；Point-LIO → /aft_mapped_to_init。
  - 地图导出：FAST-LIO 用 /map_save 服务（需 pcd_save_en=true）写 map_file_path；
    Point-LIO 无服务，只能在 SIGINT 正常退出时把分块 pcd 落盘，再 merge 成 map.pcd。

E.6 本轮追加的两条代码级疑点：结论

  疑点 A「去畸变用未扣零偏的陀螺」

    - 语义判别结果：**当前数值按协方差口径调的**。同源同类实现（FAST-LIO dog 配置

      判据用楼梯 bag 的 deg/m 与 1F low_dyaw，不许只看户外回环 RMS。

F.2 本轮提出的新主假设：雷达时间基准滞后 Δ，与转角成正比的 yaw 偏置
  机制：去畸变把整帧云转到 end_time 的 body 系。若每个点的时刻被统一多算 Δ，
        整帧云等于被多转了一个刚体旋转 R(ω·Δ)；配准无法区分"云转了"和"位姿转了"，
        于是每帧位姿偏 −ω·Δ。沿螺旋累加：
            累计 yaw 偏置 = −Δ · ∫ω dt = −Δ · Δθ_总
            ⇒ deg/m = −Δ · dθ/dz = −Δ[s] × 72.6[deg/m/s]
  为什么它比之前所有候选都更贴事实：
    ① 只动 yaw：螺旋井里 ω 主要沿竖直轴，R(ωΔ) 绕竖轴 ⇒ 纯 yaw（对应"xyz 没看到偏差"）
    ② 每层同向同角度：每层转角恒定 ⇒ Δθ∝层数（对应"所有楼层同一方向同一角度"）
    ③ 往返相消：Δθ 带符号 ⇒ 下楼与上楼相消（对应"回程又退回 0"、闭环 cm 级）
    ④ 与几何质量无关：窗外好点帮不上忙（对应"上面几层有窗外好点也没改善"）
    ⑤ 不依赖陀螺精度：yaw 来自配准而非积分（对应 D.5 的 scale 无效）
  定量：观测 0.0886 deg/m ⇒ Δ = 1.22 ms；FAST-LIO 0.1130 ⇒ 1.56 ms（同号同量级）
  判别实验（已实现，参数 lio.sensor.lidar_time_offset，默认 0）：
    扫 Δ ∈ {−3, 0, +3} ms，同 430 s 窗口，看 deg/m 是否近似线性移动 −0.0726 deg/m/ms，
    零点落在 Δ≈+1.2 ms。若三点几乎重合（<0.01 deg/m）⇒ 该假设直接证伪。
    实现：只改点的去畸变时刻，不改帧 end_time（保持 IMU 同步边界不变，单变量）。

  2) 刚性 ΔT 修正改按点时刻分配（D.7-3）：这是地图环里唯一已知的近似，
     且残差 ∝ 每帧观测修正量，方向上与转动同号；改动较大，排在 1) 之后。
  3) 残差按 30° 方位角分桶的有符号均值（P2）：验证"内壁/外壁约束互相矛盾"，
     只需在 Observe 里加 12 个浮点累加器，1 次跑。
  4) 若 1)~3) 都为空：接受"数据/几何固有"，转向外部约束（楼层高度先验、垂直度先验、
     scan-to-scan 或回环/SC-PGO）。



五-G、GenZ-LIO 跨框架对照（2026-10-22；用户提供的上游新框架）
--------------------------------------------------------------------------------
G.1 选它的理由
   GenZ-LIO（Lee et al., POSTECH，GPL-2.0）正好把"狭窄↔开阔过渡下的尺度变化"当作设计目标。
   如果本问题来自"井道里观测退化 → 配准约束不足"，它应当明显改善：
   ① adaptive_voxelization：以"降采样后点云的中位量程"的滑动均值为尺度指示 s，
      目标点数在 min_points=1000（confined）~ max_points=4000（open）之间按
      N = min + (max−min)·(1−(1−s)^p) 调度，再用 PD 控制器调体素边长
      （增益按 sqrt(s·e)、sqrt(s·r) 自适应）⇒ 窄井道自动降密度、出楼开阔自动升密度。
   ② hybrid_metric：point-to-plane + point-to-point 混合度量（lambda_po=0.05 调协方差权重），
      点对点门控按量程与"已发生的位姿修正量"自适应放宽 ⇒ 面特征退化时有点约束兜底。
   注意它没有针对"地图插入/关联规则"的特殊处理（与 FAST-LIO 家族同类），
   所以这次对照主要检验的是**观测侧成因**，不是地图侧成因。

五-H 新 bag（一圈回原点）闭环偏差对照——判据从 deg/m 换成"起终点距离"
--------------------------------------------------------------------------------
H.1 为什么换 bag、换判据
   旧 bag（A 楼楼梯间）是螺旋升/降，末端回不到起点，只能拿"每层偏角 / 高度斜率"（deg/m）
   当代理，指标本身依赖分楼层规则与高度估计。本轮新录
   /home/ywj/slam_data/livox_record_drone 为"两条楼梯一下一上、一圈回原点"，起终点物理重合：
       Δ = p_end − p_start
   直接就是累积漂移，不需要任何代理。实现见 exp/loop_error.py（新）。
   代价：只有单一场景、单一圈数，看不出"逐层同向偏移"这种形态信息。
   ⇒ 5d/5e/五-G 的 deg/m 数字与本章的闭环数字**不可混用、不可相比**（分母含义完全不同）。

H.2 统一口径（可复现性）
   1) up 方向不取任何框架的 world z：本机 MID360 为 30° 俯仰安装，只有 Super-LIO 自带
      重力对齐，FAST-LIO / GenZ 的 world z 偏离竖直约 29°，直接读 z 会虚增"竖直漂移"。
      统一做法：取 bag 起始 3 s 静态 IMU 的 mean(acc)，up_imu = −mean(acc)/|mean(acc)|，
      再用各框架自己首帧姿态转到各自世界系：up_world = R(q0)·up_imu。
      实测本 bag：|mean acc| = 1.004（Livox 驱动按 g 输出，不是 m/s²），
      up_imu = [−0.479, 0.0004, 0.878]。
   2) 起点/终点各跳过 1 s（settle=1.0）：首帧姿态未收敛、末帧有停车抖动。
   3) 双入口读 odom：Super-LIO / FAST-LIO / point_lio 用 odom.csv，GenZ 只落
      odom_tum.txt，loop_error.py 内部按此回退（否则 4 个 GenZ 格会全部报"无 odom"）。
   4) **回放必须隔离 ROS_DOMAIN_ID（本轮用 57）**。本轮首次跑 Super-LIO 只出 175 行 odom、
      地图 5017 点，日志 897 条 "imu loop back, clear buffer"；审计 bag 本身时间戳是干净的
      （/livox/lidar 步长中位 99.994 ms、/livox/imu 4.574 ms，均无回跳），根因是同 domain 上
      残留的另一份 /livox/imu 发布者（另一 bag，时间戳早约 190 天）。隔离 domain 后 60 s
      冒烟即 0 条 loop back，正式各格 odom 均 ~4670 行。
      附带噪声：不开 use_sim_time 时 "[IMU Delay] arrival latency = 2.46e+06 ms" 是预期现象
      （墙钟与 bag 时间差 ~2900 s），不是故障。
   5) GenZ 的落盘地图不可当证据：同密度下 hm on/off 的 map.pcd 逐字节等长
      （pf6 165,118,066 B、pf1 989,052,978 B）⇒ 地图保存对位姿差异不敏感。

      pf1 2.815→1.648 m（1.7×）。且 hm off 后密度效应反转（pf6 1.016 优于 pf1 1.648）
      ⇒ "GenZ 越稀越歪"主要是 hybrid_metric 与点数耦合出来的，不是 GenZ 的固有特性。
   ④ GenZ 默认配置全场最差（1.587% = FAST-LIO 的 1.8×、Super-LIO 默认的 3.0×），
      与 5e/G.5⑥ 一致 ⇒ 默认配置不进主线。
   ⑤ 位移与角度解耦：sl_imu01 位移最小但 yaw 漂 +3.96°；gz_pf6_hmoff 位移 1.016 m 而 yaw
      −5.69°；反过来 sl_base_fr6 yaw 仅 +0.36° 而位移 1.594 m。⇒ 位置与姿态是两条独立
      误差通道，"漂了多少"必须位置/角度两个数一起报，不能用一个代表另一个。
   ⑥ 转角（rotvec 模长）2.1°~12.3°，与闭环位移不同序（gz_pf1_hmoff 位移第 4、转角第 1；

五-I 扭转方向与自身转向的耦合——"点云扭、位姿不扭"的定量版
--------------------------------------------------------------------------------
I.1 观测（用户，2026-10-22）
   旧 bag（已删）与当前 drone bag 的点云地图上都看到同一现象：扭转的方向与自身上下楼的
   旋转方向绑定。典型下楼是"下一层后右转 180 度"，此时点云沿高度方向产生逆时针扭转；
   用户故意把路径改成全程左转，扭转变顺时针。**符号随转向翻转，模长基本不变。**
   这条观测的价值：它只依赖符号，不依赖任何标定或几何真值，因此比 deg/m 更难被解释掉。

I.2 drone bag 的定量核对（零成本，直接用已有 odom）
   把各 run 的姿态序列投影到竖直轴（up_world = R(q0)·up_imu，同 loop_error.py 口径），
   逐帧求绕 up 的增量再累加：
     run             净转角(度)  3D 转角和(度)  位姿闭环 yaw(度)  k(度/100 度)
     sl_base_fr6      -5689       14763          +0.36            -0.006
     sl_fr1           -5689       14740          +3.92            -0.069
     sl_imu01         -5683       14714          +3.96            -0.070
     fw1_fastlio      -5683       14835          -1.54            +0.027
     gz_pf6           -5655       14819          -0.87            +0.015
     gz_pf6_hmoff     -5695       14863          -5.69            +0.100
     gz_pf1           -5663       14769          +8.82            -0.156
     gz_pf1_hmoff     -5688       14807          -0.36            +0.006
     （净转角 = 逐帧绕 up 的有符号增量之和；3D 转角和 = 逐帧 |rotvec| 之和；
       k = 位姿闭环 yaw / 净转角 x 100，单位 度/100 度转角）
   三点读法：
   ① 全程单向：净转角 -5689 度 = -15.8 圈，且逐 5 m 高度桶的净转角**全为负**
      （-233 ~ -1111 度/桶），没有任何一段反向抵消。
      ⇒ 扭转若与转向同号，就会沿高度一路叠加，不会自相抵消——这正是"闭环误差能测到"的原因。
   ② 转角本身可信：Super-LIO 与 FAST-LIO 两条完全独立的轨迹，累计转角只差 6 度（0.1%）。
      所以 -5689 度是真轨迹属性，不是估计器噪声。
   ③ 位姿几乎不承接转角：同一段 -5689 度单向旋转，位姿闭环 yaw 只有 +0.36 度（最好）到
      +8.82 度（gz_pf1），即每 100 度转角只漂 0.006~0.156 度。且 k 的符号随框架变
      （Super-LIO 三格同负、GenZ 三格同正、FAST-LIO 正）⇒ 这几度残差不是同一个机制，
      量级上已足够小。**位姿层面的 yaw 传递率 <1%**，与 5d 的硬约束一致。

I.3 与旧 bag 的几何判据合并
   旧 bag 的 deg/m 是在**点云地图**上量的（每层偏角 / 层高），不是位姿漂移：
   每层 -0.532 度、层高 3.70 m ⇒ 每层掉头 180 度对应 -0.30 度/100 度转角。
   于是两条独立判据拼成一个完整图像：
     点云层：k_cloud 约 -0.3 度/100 度转角（旧 bag 几何真值，drone bag 目视同量级）
     位姿层：<0.01~0.15 度/100 度转角（drone bag 闭环）
   ⇒ 扭转**几乎全部发生在点云层面**（单帧点云或入图环节），位姿只承接 1% 左右。
     这解释了旧 bag 上"整帧云刚体多转、位姿 yaw 只让位 3%"（5d），也解释了为什么
     "点云肉眼可见歪、而 odom 闭环 yaw 却很小"（本轮）。两者不矛盾，是同一件事的两侧。

I.4 为什么这不推翻 5d，反而修好了 5d 的结论
   5d 的实验只证明：改 lidar_time_offset（-3/0/+3/+10/+50 ms）时，等效 Delta 只有
   -0.19/0/+0.19/+0.31 ms（传递率 3%~6%，R^2 = 0.02）⇒ **这个参数不是那个旋钮**。
   但它没有、也无法否定"yaw 误差正比于累计转角"这个形式——恰恰相反，用户的方向实验
   是该形式的直接证据：形式只要求"每单位转角贡献一个固定小偏差"，符号自然随转向翻转。
   ⇒ 后续找的不是"时移参数"，而是"哪个环节在每单位转角上丢/多算了一点点角度"。

I.5 只剩两个环节（互斥，可用一次离线实验判定）
   (a) 帧内去畸变：单帧点云自身被扭。表现为同一帧扫到的墙面是弯的/斜的，残差随 |w| 增长。
   (b) 帧间入图：单帧点云是平的，但整帧被按错位姿（时间错位 Delta，或用了非插值的关键帧位姿）
       插入地图，云相对地图整体转了一个小角度。残差与 |w| 无关，而与帧间转角有关。
   判别方法（不需要真值、不需要新 bag）：
     取若干帧原始 /livox/lidar，按 points[i].offset_time 用 odom 姿态插值做运动补偿，
     再对帧内最大的竖直平面做 PCA/RANSAC 拟合，统计残差 vs 该帧 |w_up|。
     若残差随 |w| 显著增长 ⇒ (a)；若补偿后残差恒定且很小，而地图仍歪 ⇒ (b)。
   注意本机旋转很快（drone bag 的 |w_up| 中位 12.9 度/s、p90 70.4 度/s、峰值 192.8 度/s），
   帧内 100 ms 最多转 19 度，10 m 处弧长 3.4 m，所以不做补偿无法直接看平面度。

I.6 下一步实验（按性价比排序）
   1) 离线 I.5 判别（现成 bag，零新增采集）：先判 (a)/(b)，再决定改哪里。
   2) 新录"原地单向纯旋转"：同一位置右转 5 圈、再左转 5 圈各一个 bag（各 1 min，手持即可）。
      零平移 ⇒ 排除一切平移/几何相关机制；5 圈 x 360 度 = 1800 度转角，若 k_cloud 为
      -0.3 度/100 度，应看到 -5.4 度扭转，且左右两包符号相反、模长相同。
      这是把"转角相关"从相关升为因果的最便宜实验，也能直接标定 k_cloud。
      对照：同一位置静止 60 s，地图不应有拖影。
   3) drone bag 分段投影：把下楼段与上楼段分别用 odom 投成两幅世界系点云，比较同一面墙的
      错开角。两段同向旋转，若 k_cloud 恒正/恒负，错开角应叠加而非抵消，可直接量出 k_cloud。
   4) 只有当 1) 指向 (a) 时，才值得回去动去畸变的插值/时间窗；指向 (b) 则落在入图位姿
      查询上（与五-F.5 的地图闭合项合并）。

J.7 算力实测（2026-10-22，同一段 60 s bag，桌面 i7-7700 @3.6GHz，domain 57）
   此前**没有任何**运行时长/算力记录：Super-LIO 的 node.log 只有内置计时器，GenZ 的 node.log
   只有 4 行（起停 + 存图），两边都不含"每帧耗时"。本次补测。
   方法：perf_probe.py（新增，exp/ 下）每 0.2 s 读 /proc/<pid>/stat 的 utime+stime 与
        status 的 Threads/VmRSS，取稳态段斜率得平均占核数，再按 10 Hz 输入折成"每帧 CPU 秒"。
        这样得到的是**总计算量**，与是否多线程无关，可直接用于估算单核耗时。
   结果（三个时间窗一致，静止段/运动段无差别）：
     GenZ-LIO  pf6   1.79 ~ 1.81 核   179 ~ 181 ms/帧   峰值线程 14   RSS 165 MB
     Super-LIO fr6   0.25 ~ 0.28 核    25 ~  28 ms/帧   峰值线程 18   RSS 301 MB
   => GenZ 每帧计算量是 Super-LIO 的 6.6 ~ 7.0 倍。
   物料规模：同一 60 s 片段 GenZ map.pcd 19.4 MB、Super-LIO 0.39 MB；
        整包 470 s：GenZ pf6 10.3 M 点 / 158 MB，pf1 61.8 M 点 / 944 MB；Super-LIO 12 万点 / 1.9 MB。
   RK3588 单核折算（A76 @2.4GHz vs i7-7700 @3.6GHz，单核约 0.45 倍 => 乘 2.0~2.4）：
     Super-LIO：约 55 ~ 65 ms/帧 => 10 Hz 下吃 0.55 ~ 0.65 个 A76 核，**可以跑**，余量约 1.6 倍
     GenZ-LIO：约 360 ~ 430 ms/帧 => 上限约 2.3 ~ 2.8 Hz，**单核跑不动 10 Hz**
        （GenZ 在桌面上已要 1.8 核才勉强 10 Hz，压到单核只会更慢；这不是线程没开够的问题）
     FAST-LIO：未实测，结构上与 Super-LIO 同量级，按同一档估。
   两个坑：
   ① Super-LIO 自带的 [Observe](2.6 ms)/[Undistort](0.28 ms)/[UpdateMap](0.07 ms) 合计约 3 ms/帧，
      而实测总 CPU 是 27 ms/帧 => 内置计时只覆盖约 10%，**不能用它估算平台可承载性**。
   ② GenZ 完全无打点，必须靠外部采样；perf_probe.py 可直接拿到 3588 上复用。
   结论：以"3588 单核 10 Hz"为硬约束，候选集只应保留 Super-LIO / FAST-LIO；
        GenZ-LIO 需要至少 2 个 A76 核才谈得上实时。
   复现：

     cd lio/genz-lio/exp   && python3 -B ../../Super-LIO/exp/perf_probe.py genz_lio_node out.csv &
     ./run_one.sh gz_perf 6 60
     cd lio/Super-LIO/exp  && python3 -B perf_probe.py super_lio_node out.csv &
     ./run_one.sh sl_perf 6 0.25 0.1 0.1 0.25 60

K.4 判读
   1) 法向质量加权是唯一大幅正收益的代码开关：sigma=0.05 把闭环从 1.594 m 压到 0.646 m
      （-59.5%），占路径 0.531%->0.215%，转角 3.500->1.013 度。它同时修掉了基线里唯一
      系统性分量：竖直偏差 +0.580 -> -0.019 m（其余格子的竖直都在 +-0.03 m 内，只有基线
      是 +0.58 m，说明基线在整圈里缓慢抬升）。
   2) sigma 有明确最优带 0.035~0.06：
        0.02 -> 0.868 | 0.035 -> 0.845 | 0.05 -> 0.646 | 0.06 -> 0.794 | 0.08 -> 1.081 | 0.12 -> 2.151
      机制上 q = fit_res / sigma，sigma 越大权重越接近 1（=不加权）：sigma=0.12 时 2.151 m
      已经把基线（1.594 m）跑输，说明"加权太软"比"不加权"更差（它改变了解的类型但没有
      真正降权，只引入了偏置）。继续把 0.04~0.06 细分收益有限（相邻档已在 0.15 m 平台）。
   3) merge_dist 收紧到 0.05 单独有效（0.64x），但 yaw 从 +0.36 恶化到 +3.00 度，是"位移换
      姿态"。与 nw05 组合反而退化（1.073 m）=> 两者作用在同一环节（陈旧/高残差代表点污染
      法向与残差），不可叠加。
   4) rep_mode=1 与 HKNN 分组在本 bag 上依旧无效（0.97x / 1.01x），与五-B 户外结论一致。
      这两个开关可以从 backlog 删除（保留默认），不必再占预算。
   5) 非可加性是本章最重要的工程结论：
        imu01 单独 0.305 m；imu01 + nw05 = 0.971 m（差 3.2x）
        nw05 单独 0.646 m；nw05 + merge005 = 1.073 m
      "最优参数 + 最优开关"不是最优解。要拿全局最优必须做 imu_na/ng x normal_sigma 二维网格。

七、判据决策树
--------------------------------------------------------------------------------
Q1 跳变是否与 cond_yk 峰值 / Qk 非有限值同帧？
   是 → 数值问题，先上 P0-2 再复测。
   否 → Q2。

Q2 跳变是否与 ptsize > 20000 同帧？
   是 → 越界，先上 P0-1。
   否 → Q3。

Q3 楼道段 htvh_t_eig3/eig1 是否 < 0.05，且 λ3 特征向量≈运动方向？
   是 → 几何退化（设计边界），漂移量由 IMU 偏置决定，转 Q4。
   否 → 几何可观测，漂移来自 IMU/外参/尺度，直接 Q4。

Q4 逐帧修正量 dp 投影到世界系 / 机体系：
   机体系方向基本恒定、世界系随航向转 → 机体系常值加速度偏置
        （重力对齐残差 / imu_scale / ba / 外参）
   世界系方向基本恒定 → 观测侧偏置（掠射法向 / 平面阈值）
        → 实验 1（法向质量加权，已实现，开关 lio.observe.normal_weight_en；
           户外回环实测 RMS 0.102 m，与基线同量级，未证明有效）
   两者都不恒定且随时间单调增 → 退化方向无约束 + 零偏积分
        → 调参解决不了，需 scan-to-scan / 子图 / 回环。

Q5 逐层相对位姿误差随“转角”线性增长还是随“高度”线性增长？
   随转角 → bg（偏航零偏）
   随高度 → ba / imu_scale（比力尺度）
   （数据来自 PCD/scans_*.txt 的位姿，不需要新埋点）

八、离线验证（用已有落盘数据）
--------------------------------------------------------------------------------
1. 每层平台取一个关键位姿，计算相邻层相对位姿 ΔT_k。
2. 分解为 Δyaw_k 与机体系下的 Δp_k。
3. 画 Δyaw_k - k、Δp_k - k：
   - Δyaw_k 有常值偏置 → bg；
   - Δp_k 在机体系有常值偏置 → ba / tilt / imu_scale；
   - 两者随 k 增大而发散 → 退化方向无约束。
4. 与 CSV 中同时间段的 ba/bg/imu_scale/g_ 曲线叠加确认。

九、不要动的地方（保住性能优势）
--------------------------------------------------------------------------------
- scalar=float 的整体存储：保持不动，只把两处 18x18 求逆转 double。
- 5 近邻 KNNHeap 与 HKNN 分组遍历：不扩 K、不改列表（除非做实验 3 的配套）。
- OctVox 的 8 子体素 + 增量均值 + 20 点上限：保留；实验 2 已做成 rep_mode/merge_dist
  两个开关，clamp 版实测为恒等（见五-B），默认仍是论文的增量均值。
- VoxelGridClosest 的“离体素中心最近”规则：保留（这就是论文设计）。
- effect_mask_ 定长数组：保留，只加钳制。
- need_converge 时跳过 KNN 重搜索：保留。
- DenseThread 异步全量链路：保留。

十、风险与注意
--------------------------------------------------------------------------------
1. 任何地图表示改动（实验 2/5）都必须全新建图，旧地图与新代码不可混跑。
2. 运行时参数回调对 voxel_fliter_size 无效；实验必须重启节点。
3. `lio.sensor.enable_downsample` 在正常 LIO 模式不生效，不要用它来“关体素”。
4. 加埋点后先地面 bag 回放确认输出正常，再实飞；楼梯间飞行本身有风险。
5. 实验顺序：P0-1/P0-2 → 埋点 → 实验 1/2 → 实验 3/4 →（必要时）实验 5。
   实验 3/4 已在户外回环完成一轮（五-A）；代码级实验 1/2/5 + HKNN 分组已完成
   一轮（五-B，脚本 exp/run_code_all.sh）。楼梯数据到手后直接复用两套脚本复测。
6. 代码级开关（normal_weight / rep_mode / clamp / max_points / merge_dist /
   hknn_max_group / order_scale）都是每帧读全局，但建图是有状态的：
   同一次运行中途改值会造成“前半图与后半图规则不同”，必须整轮重启。
7. 若最终确认是“退化方向 + 零偏积分”，优先工程手段（关键帧约束、楼层高度先验、
   回环/SC-PGO），不要继续压 filter_rate 或调观测权重。
